# TMD 語言規格（TmdSwift 實作版）

版本：0.1（對應目前 TmdSwift parser）  
語言：繁體中文（[English Version](TMD-Language-Specification.en.md)）

## 1. 文件目的

本文件定義目前 TmdSwift 所接受的 TMD（Timebase Mark Down）文字格式。
文件描述的是「目前實作的行為」，不是未來功能的提案。歷史設計、原始 TMDLang
文件以及尚未實作的語法，另見 [`Band-Score.syntax.zh_TW.md`](Band-Score.syntax.zh_TW.md)。

TMD 是用純文字描述歌曲結構、樂器段落、首調唱名、和弦與播放順序的格式。
一個 TMD 檔案解析後會形成 `Sheet`，再由 MIDI、MusicXML、LilyPond、ABC 或
WAV 輸出模組使用。

## 2. 最小檔案結構

```text
::SCORE::
** 歌曲名稱 **
!= 120
?= C
<4/4>

段落名稱:樂器名稱@|0|{
    <4*>
    1 2 3 4
}

-> 段落名稱 ->#
```

檔案必須以 `::SCORE::` 開頭。其後可出現歌曲標題、速度、調性、拍號、段落
和播放順序。解析器目前允許這些項目的順序較為寬鬆；同一項目重複出現時，
後出現的值會覆蓋前一個值。

## 3. 空白與註解

空白、Tab、換行都會被忽略，因此下列寫法在詞法上等價：

```text
!=120
!= 120
! = 120
```

區塊註解使用 `/*` 和 `*/`，可以跨越多行：

```text
/* 這段文字不會成為音樂資料 */
```

目前沒有行註解語法。未閉合的區塊註解會一路忽略到檔案結尾。

## 4. 歌曲標題、速度、調性與拍號

### 4.1 標題

```text
** 三天三夜 **
```

`**` 之間的識別字、數字和音符數字會組合成標題；多個詞之間以單一空格
保存。標題不是必要欄位，未提供時 `Sheet.name` 為空字串。

### 4.2 速度

```text
!= 133
!= 120.5
```

速度保存為 BPM 的 `Double`。整數和小數皆可。段落內也可使用 `{!=145}` 或
`{!+30}` 改變後續播放的絕對或相對速度。

### 4.3 調性

```text
?= A'
? = C
```

調性保存為字串，不在 parser 層驗證調號是否合理。因此 `C`、`A'`、`Bb` 或
其他可被讀成識別字的內容都可能被接受。調性轉換 `{?+5}` 是播放順序中的
相對轉調，不是這裡的檔頭調性欄位。

### 4.4 拍號

```text
<4/4>
<3/4>
```

前一個數字是每小節拍數，後一個數字是拍子的音符值。拍號保存為
`Beat(count:noteValue)`。

## 5. 段落與軌道

段落語法如下：

```text
段落名稱:樂器名稱@{
    section+
}

段落名稱:樂器名稱@|起始小節|{
    section+
}

/* 抽象段落／主題原型（不綁定樂器，供 S-Expression 巨集引用） */
段落名稱{
    section+
}
```

例如：

```text
intro:Piano@|0|{
    <4*>
    1 2 3 4
}

intro:Guitar@|+4|{
    <16*>
    1_ - 1_ -
}

/* 抽象卡農主題原型 */
Theme{
    <4*>
    3^ 2^ 1^ 7 | 6 5 6 7 | 1^ 7 6 5 | 4 3 4 2 |
}
```

欄位意義如下：

| 欄位 | 意義 |
| --- | --- |
| 段落名稱 | 例如 `intro`、`A`、`chorus`、`Theme` |
| 樂器名稱 | 例如 `Piano`、`Guitar`、`CHORD`；若為抽象原型則省略冒號與樂器名稱 |
| 起始小節 | 以整數表示；省略時為 `0` |

起始位置可以是正數、零或負數；負數表示提前進場，例如 `@|-1|`。

同一個段落名稱可以有多個樂器段落。它們會各自保存為一個 `Paragraph`，
不會在 parser 層合併。未指定樂器名稱與起始小節的段落會保存為抽象段落（`instrument` 為空），不直接輸出至時間軸，而是由播放流程中的 S-Expression 巨集引用與實例化。

## 6. Section 與基本節奏單位

每個 section 以 `<n*>` 開始：

```text
<4*>
<16*>
```

`n` 會保存為 `Section.noteLength`，表示此段落使用的基本細分單位。
section 會持續讀取音樂單位，直到遇到下一個 `<n*>`、段落結尾 `}` 或檔案結尾。

section 中可使用 `|` 作為排版用小節線。它在目前 parser 中會被忽略：

```text
| 1 2 | 3 4 |
```

### 6.1 段落內 directive

directive 可放在 section 的音樂單位之間，位置以它前面的基本單位數表示：

```tmd
<4*>
1 2 {!=140} 3 4
{!+10}
{?+2}
{?=D}
{?=fixed}
{<3/4>}
```

支援的種類包括：
- 絕對速度（`{!=140}`）與相對速度（`{!+10}`）
- 絕對調性（`{?=D}`）與相對移調（`{?+2}`、`{?-2}`）
- **固定音高（`{?=fixed}` 或 `{?fixed}`）**：將該軌道段落強制鎖定為固定音高（`keyOffset = 0`），不受外層播放順序中轉調指示（如 `-> {?+3} -> ...`）的影響。極為適合定音鼓（Timpani）、音效（Sound FX）或無移調打擊樂器。
- 局部拍號（`{<3/4>}`）

MIDI 會將速度與拍號寫入 conductor track；MusicXML、LilyPond 和 ABC 會輸出相應標記。

## 7. 音樂單位

### 7.1 首調唱名音符

基本音符是 `1` 到 `7`：

```text
1 2 3 4 5 6 7
```

升降記號必須直接接在音級後面：

```text
1'     /* 升 Do */
2,     /* 降 Re */
```

八度以 `^` 或 `_` 表示，每一個符號代表一個八度：

```text
1^     /* 高一個八度 */
1^^    /* 高兩個八度 */
1_     /* 低一個八度 */
1__    /* 低兩個八度 */
1'^    /* 升 Do，高一個八度 */
```

升降記號和八度記號的順序是固定的：先寫升降記號，再寫八度記號。
同一音符重複出現升降記號時，最後一個記號決定 accidental；八度符號則累加。

### 7.2 和弦

和弦使用中括號：

```text
[Cmaj7]
[Am]
[1]
[6m]
```

parser 會將中括號內容解析為 `ChordSymbol`。根音支援 C～B 字母或 1～7
唱名度數，品質包含大三和弦、小三和弦、七和弦、減和弦、增和弦、掛留和弦與
power chord；未列入內建集合的 suffix 會以 `.custom(String)` 保存，因此仍能
表達 `C7#9` 等延伸和弦。前後空白會移除，但 parser 不驗證和弦是否符合調性。

### 7.3 複音／同時發聲雙音（Multi-Notes / Dyads）

使用 `+` 號連接兩個或多個音符，表示在同一時間、同一拍位上同時演奏的多個非和弦音符（如小提琴雙音、鋼琴雙聲部合音）：

```text
1+3        /* 同時彈奏 1 與 3 */
1+5--      /* 同時彈奏 1 與 5，並以延音線延長時值 */
1^+3       /* 支援八度與升降記號 */
1+3+5      /* 支援三個以上音符的音叢或自定義多音結構 */
```

在連音（tuplet）中亦可使用：

```text
(1+3 2+4)%(--)
```

在 MeasureCheck 與節拍計算中，每個以 `+` 連接的多音組計算為 1 個基準單位（unit），不會使小節時值重複膨脹。

### 7.4 延音／複製線

單一 `-` 會解析為 tie：

```text
1 - - -
[Cmaj7] -
```

實際延音時值由 exporter 依前後音樂單位與 section 的節奏解讀。

### 7.5 連音／節奏群組

括號內放置多個音樂單位，再以 `%(...)` 指定群組所佔的基準長度：

```text
(1 2 3)%(--)
(7, 1)%(--)
```

`%(--)` 中每一個 `-` 代表一個基準長度，因此上例的 `length` 是 `2`。
括號內可包含音符、和弦、tie，以及其他可被 parser 讀取的音樂單位。

若沒有連音標記，單一音樂單位會形成一個 `length = 1` 的群組：

```text
1 2 [C] -
```

等同於四個各含一個 unit 的 `UnitGroup`。

## 8. 播放順序、轉調與 S-Expression 巨集

播放順序由 `->` 開始，以 `->#` 結束：

```text
-> intro -> A -> B ->#
```

### 8.1 靜態段落名稱
段落名稱會保存為 `Order.name`：

```text
-> intro
```

### 8.2 轉調指令
相對轉調使用：

```text
-> {?-3}
-> {?+3}
```

內容會保存為 `Order.relative` 的字串，例如 `-3` 或 `+3`。絕對轉調使用：

```text
-> {?=C}
-> {?=A'}
```

內容會保存為 `Order.absolute` 的字串。

### 8.3 S-Expression 巨集指令
播放流程中支援 S-Expression 巨集，用以精確排程複調多軌結構，避免手動算小節偏移的錯誤：

```text
-> (canon Theme (Violin1 Violin2 Violin3) 2)
-> (layer (canon Theme (V1 V2) 2) (loop Bass Cello 8))
```

核心指令包括：
- `(play <主題> <樂器>)`：將抽象主題綁定至指定樂器軌道。
- `(loop <主題> <樂器> <次數>)`：將主題連續重複演奏指定次數（如固定低音 Ground Bass）。
- `(canon <主題> (<樂器列表...>) <間隔小節數>)`：自動依照間隔小節將主題錯開排入各樂器軌。
- `(layer <表達式1> <表達式2> ...)`：同時並行播放多組表達式。
- `(seq <表達式1> <表達式2> ...)`：依序前後串聯播放多組表達式。
- `(vary <主題> <修飾子...>)`：主題變形，支援簽名半音移調（`+7`、`-5`、`+12`）、旋律反轉倒影 `flip`、逆行 `reverse`、平行大小調轉換 `minor` / `major`。

`->#` 是播放順序終止標記。parser 遇到它就結束整個 Sheet 的解析；其後內容會被忽略。

## 9. AST 對照

| TMD 概念 | 型別定義 |
| --- | --- |
| 拍號 | `Beat` |
| 音符 | `Note` |
| 和弦 | `ChordSymbol`（根音為 `ChordRoot`，品質為 `ChordQuality`） |
| 音符／和弦／tie | `Unit` |
| 連音群組 | `UnitGroup` |
| `<n*>` 與其內容 | `Section` |
| 段落與樂器軌 | `Paragraph`（抽象主題時 `instrument` 為空） |
| 播放順序 | `Order`（支援 `name`、`relative`、`absolute`、`macro`） |
| 完整歌曲 | `Sheet` |

目前 `Unit` 支援 `.note`、`.chord`、`.tie`、`.rest` 和 `.percussion`；歌曲
metadata 保存於 `Sheet.metadata`，段落 directive 保存於 `Section.directives`。

## 10. Exporter 能力矩陣

所有 exporter 在輸出前，皆會透過 `TMDMacroEvaluator` 將 S-Expression 巨集自動展開為具體的時間軸軌道與小節事件，因此所有格式（MIDI、MusicXML、LilyPond、ABC、WAV、REAPER、ChordPro）皆完整支援巨集播放流程。

## 11. 完整範例（D 大調卡農 S-Expression 巨集）

```tmd
::SCORE::
** Canon in D **
~ "composer: Johann Pachelbel"
~ "arranger: S-Expression Edition"
!= 56
?= D
<4/4>

/* 固定低音原型 (Ground Bass, 2 小節) */
Bass {
    <4*>
    1_ 5__ 6__ 3__ | 4__ 1__ 4__ 5__ |
}

/* 卡農主題原型 (Theme, 4 小節) */
Theme {
    <4*>
    3^ 2^ 1^ 7 | 6 5 6 7 | 1^ 7 6 5 | 4 3 4 2 |
}

/* 前奏：大提琴先奏一次固定低音 */
intro:Cello@|0|{
    <4*>
    1_ 5__ 6__ 3__ | 4__ 1__ 4__ 5__ |
}

/* 尾奏：各部匯流終止 */
outro:Violin1@|0|{ <1*> 1^--- | }
outro:Violin2@|0|{ <1*> 3--- | }
outro:Violin3@|0|{ <1*> 1--- | }
outro:Cello@|0|{   <1*> 1_--- | }

/* 播放流程：由大提琴反覆低音 4 次，並由三把小提琴各間隔 2 小節嚴格卡農進入 */
-> intro
-> (layer
     (canon Theme (Violin1 Violin2 Violin3) 2)
     (loop Bass Cello 4))
-> outro
->#
```

這個範例示範了抽象主題聲明、S-Expression 巨集的平行重疊（`layer`）、卡農錯位延遲（`canon`）與固定低音循環（`loop`），完全由編譯器自動計算小節與軌道對齊。

## 12. 解析與編碼

`TmdParser` 可從以下來源解析：

- Swift `String`
- `Data`
- 本地檔案 URL
- 檔案路徑或 `file://` URL 字串

以 `Data` 解析時，工具會嘗試偵測文字編碼，支援 UTF-8、Big5、GB18030 等
常見編碼。解析失敗時目前 API 以 `nil` 表示；parser 尚未提供行號、欄號或
結構化診斷訊息。

## 13. 相容性與未來擴充

本文件的版本只保證目前 TmdSwift parser 已經能夠解析並保存在 AST 中的語法。
未來若加入新語法，應遵守以下原則：

1. 不改變既有合法 TMD 的音樂意義。
2. 新增 AST 型別或欄位時，明確記錄 exporter 的處理方式。
3. 為每個新語法加入 parser、formatter 與至少一個 exporter 的測試。
4. 將原始 TMDLang 語法和 TmdSwift 擴充語法分開標示。
5. 需要無法相容的變更時，提升規格版本並提供 migration 說明。
